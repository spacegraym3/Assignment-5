(1) Running 'source bench.sh 1' starts using around 500 kb of memory at the beginning.  It continues to significantly increase for each subsequent call.  It tops out at around 394000 kb.
(2) Running 'source bench.sh 5' does exactly the same except it is runnng 5 processes simultaneously versus 1 process in the previous run.
(3) The normal file reads take about twice amount of memory than the mmap reads.  Initially, the memory usage hits the same value for both.  However, mmap reads drop to half the memory pretty quickly.  Reason is the normal read has to store the image in memory for all 5 processes.  With mmap reads, all 5 processes are all reqding from the same memory.
(4) A minor fault occurs when the needed data is already in physical memory (RAM) but not mapped in page table mapping.  In this case, the page table is updated to point to the physical page (frame).  Since it was already present, there is no need to disk I/O.   A major fault occurs when the data is not in RAM so the OS has to retrieve the frame data from the disk which slows down the operationn considerably.
